  <action>
Skapa en ny Joi schema för `POST /api/reports/attendance/raw` request-body.

Krav (Phase 1):

- `from`: required string `YYYY-MM-DD`
- `to`: required string `YYYY-MM-DD`
- `page`: optional int >= 1 (default 1)
- `pageSize`: optional int (default 25), cap t.ex. 100
- Filterfält (alla optional):
  - `studentId` (24-hex)
  - `studentName` (string, contains)
  - `classScheduleId` (24-hex)
  - `instructor` (string)
  - `status` (array av tillåtna: present/absent/late/excused)

Sätt `stripUnknown: true` för att undvika oväntade filter.
  </action>

<task type="auto">
  <name>Task 2: Implementera ReportService med aggregate + facet</name>
  <files>src/services/ReportService.ts</files>
  <read_first>src/services/AttendanceService.ts, src/models/Attendance.ts</read_first>
  <action>
Skapa `ReportService` som exponerar en metod i stil med `getRawAttendanceReport(query)`.

Implementationskrav:

- Tolka `from/to` enligt CONTEXT:
  - Europe/Stockholm
  - inklusiva hela dagar
  - UI skickar date-only
- Query Attendance med:
  - `$match` på `date` (>= start, <= end)
  - Additional match på status/studentId/classScheduleId
- Join för berikning:
  - `$lookup` students (student.name)
  - `$lookup` classschedules (date/start_time/end_time + class_id)
  - `$lookup` classes (class.name + instructor)
- Paginering:
  - Stabil default-sort (t.ex. `date desc, recorded_at desc, _id desc`)
  - `$facet` för `{ items, total }`
- Returnera DTO som matchar Phase 1 kolumner.

Obs: Undvik att basera instruktör på `sessions` i `ClassSchedule` i Phase 1 (inkonsekventa fält). Använd `Class.instructor` tills vidare.
  </action>

  <acceptance_criteria>

    - Varje item har studentName + className + start/end + status + category + recorded_by + recorded_at
  </acceptance_criteria>
