  <action>
Create a new Joi schema for the `POST /api/reports/attendance/raw` request body.

Requirements (Phase 1):

- `from`: required string `YYYY-MM-DD`
- `to`: required string `YYYY-MM-DD`
- `page`: optional int >= 1 (default 1)
- `pageSize`: optional int (default 25), cap e.g. 100
- Filter fields (all optional):
  - `studentId` (24-hex)
  - `studentName` (string, contains)
  - `classScheduleId` (24-hex)
  - `instructor` (string)
  - `status` (array of allowed values: present/absent/late/excused)

Set `stripUnknown: true` to avoid unexpected filters.
  </action>

<task type="auto">
  <name>Task 2: Implement ReportService with aggregate + facet</name>
  <files>src/services/ReportService.ts</files>
  <read_first>src/services/AttendanceService.ts, src/models/Attendance.ts</read_first>
  <action>
Create `ReportService` that exposes a method along the lines of `getRawAttendanceReport(query)`.

Implementation requirements:

- Interpret `from/to` according to CONTEXT:
  - Europe/Stockholm
  - inclusive full days
  - the UI sends date-only
- Query Attendance with:
  - `$match` on `date` (>= start, <= end)
  - additional match on status/studentId/classScheduleId
- Join for enrichment:
  - `$lookup` students (student.name)
  - `$lookup` classschedules (date/start_time/end_time + class_id)
  - `$lookup` classes (class.name + instructor)
- Pagination:
  - Stable default sort (e.g. `date desc, recorded_at desc, _id desc`)
  - `$facet` for `{ items, total }`
- Return a DTO matching the Phase 1 columns.

Note: Avoid basing instructor on `sessions` in `ClassSchedule` in Phase 1 (inconsistent fields). Use `Class.instructor` for now.
  </action>
  <verify>pnpm test -- -t "ReportService"</verify>
  <acceptance_criteria>
    - Result contains items + total + page + pageSize
    - Every item has studentName + className + start/end + status + category + recorded_by + recorded_at
  </acceptance_criteria>
  <done>The service can return paginated raw rows from test data</done>
</task>
